# Root layout and response clarity

## Behavior

General Development Practices in `AGENTS.md` now require explicit customer
approval before creating a new file at a repository root. Propose its name and
purpose before approval. Existing authorized edits do not require another approval.
Use established implementation, test and documentation directories by default.

User-facing explanations should use simplified technical writing principles for
about 80% of their content: short sentences, active voice, consistent terminology
and concrete verbs. The remaining complex material can use normal technical
language when simplification would reduce accuracy. Adapt clarity principles to
the user's language and preserve code, identifiers and exact requirements.

This is a writing target, not a counted ratio or formal certification.
[ASD-STE100](https://www.asd-ste100.org/STE_faq.html) includes writing rules and
a controlled English dictionary; adopting selected clarity principles in Russian
does not constitute compliance with the complete standard.

## Acceptance and operational constraints

- A proposed new root file needs approval naming its purpose and path.
- Files within established directories follow the authorized task scope.
- A normal Russian technical response stays in Russian, uses clear prose and
  retains precise technical terms where needed.
- No automated compliance score or 80/20 word count is claimed.
- Install/upgrade distributes the updated baseline through the existing managed
  guidance mechanism; edited target guidance follows normal conflict protection.
